# なぜトークンが見つけにくかったのか（2026-09-05）

この日、「全権限のトークンはもう作ってあるはず」という作者の記憶が正しかったのに、
AI側が「無い」と2回報告して手戻りが出た。**同じことを繰り返さないために、原因を残す。**

---

## 何が起きたか

作者「トークンでやって」
→ AI「手元の環境変数を確認 → **0ゾーン・0アカウント** → 使えません。新規に作ってください」

作者「`web-ios-android` に全権限のを作ったはず、もう一度みて」
→ AI「`.env.local` と `.secrets-local/` を確認 → Cloudflareのトークンは無し。やはり新規作成を」

作者「**全ての権限があるものをキットにいれたはずですよ**」
→ AI「GitHub Secrets を確認 → **あった**。実測すると21ゾーン・8Worker・Access可」

**結論: 作者が正しく、AIが2回外した。**

---

## ★根本の原因: 「同じ名前で、中身が違うものが3つあった」

`CLOUDFLARE_API_TOKEN` という**同じ名前**の値が、少なくとも3箇所にあり、
**権限がバラバラ**だった。

| 置き場所 | 中身（実測） | 使える場面 |
|---|---|---|
| **この端末の環境変数** | ゾーン **0件** / Workers 不可 | ほぼ何もできない |
| **GitHub Secrets**（2026-08-30更新） | ゾーン **21件** / Workers 8件 / Access 可 | ★本命 |
| `CLOUDFLARE_DNS_TOKEN`（別セッションで設定） | DNS編集用 | DNSのみ |

名前が同じなので、**片方を見て「これが例のトークンだ」と早合点した。**
実際には別物で、権限が桁違いだった。

---

## ★見つけにくかった理由（4つ）

### 1. 探した場所が「ファイル」に偏っていた
`.env.local` / `.secrets-local/` / `.dev.vars` は探したが、
**GitHub Secrets を最初に見なかった**。
secretsは `gh secret list` で**名前と更新日だけは読める**（値は読めない）。
これを最初にやれば、`2026-08-30更新` という新しさから当たりが付いた。

### 2. 「見つからない」と「権限が無い」が同じ見た目になる
Cloudflare API は、権限が無いゾーンを**エラーにせず、単に返さない**。

```
success: true / 件数: 0 / errors: []
```

これは「そんなゾーンは無い」とも「あなたには見えない」とも読める。
**`success: true` なのに0件、はほぼ権限不足のサイン**だと知らないと誤読する。

### 3. 記憶の中で「キット」と「リポジトリ」が結びついていた
作者の「キットに入れた」は **GitHub Secrets（CIの実行環境）** のことだったが、
AIは `web-ios-android` という**ディレクトリ**を探しに行った。
「キット」＝置き場所の名前ではなく、**仕組み全体**を指していた。

### 4. 権限が機能ごとに独立していることを、確かめる前に判断した
最終的に見つかったトークンでも、**Email Routing だけは通らなかった**。
「21ゾーン見える＝何でもできる」ではない。
`web-ios-android/CLAUDE.md` に既に
「**ゾーンが見えている＝編集できる、ではない**」と書かれていたのに、
それを読む前に結論を出していた。

---

## ★次に同じ状況になったらこうする

**1. 秘密を探すときは、この順で見る**
```bash
gh secret list --repo <owner>/<repo>     # ← ★まずここ。名前と更新日は読める
gh variable list --repo <owner>/<repo>   #   変数側も見る
env | grep -i <service>                  #   端末の環境変数
ls -a .secrets-local/ .env* .dev.vars    #   ファイル
```

**2. 「無い」と報告する前に、必ず全部を見る**
1つ見て無かった時点で「無い」と言わない。
**作者が「あるはず」と言ったら、それはたいてい正しい**（作った本人なので）。
探し方を変える。

**3. 権限は「実際に叩いて」確かめる**
トークンの権限一覧は画面でしか見られないが、**やりたい操作を1回叩けば分かる**。
読み取りだけの `check` を先に走らせて、できること/できないことを一覧にする。
→ 実装例: `.github/workflows/cloudflare-setup.yml` の `mode=check`

**4. `success: true` で0件なら、権限を疑う**
エラーが無いことは「権限がある」ことを意味しない。

---

## この件で作ったもの

| もの | 何のため |
|---|---|
| `.github/workflows/cloudflare-setup.yml` | トークンを手元に持ってこずに設定する |
| `scripts/cloudflare-setup.mjs` | check → 設定 の順で安全に進める |
| `web-ios-android/CLAUDE.md` への追記 | 権限が機能ごとに独立していることを一般化して残した |

★この方式なら、**トークンの値は誰の目にも触れない**。
GitHub Secrets から workflow の中だけで使われ、ログにも出ない（redact してある）。
