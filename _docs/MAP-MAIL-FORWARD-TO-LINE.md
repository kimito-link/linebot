# 地図: 通知メールの転送をLINEへ（wayfinder 手順1）

作成: 2026-09-05。司令塔が実コードと実xlsxを読んで作成。**推測は「未確認」と明記した。**

## 何をしたいか

ランサーズ/ココナラの通知メールを、件名パターンで振り分けてChatworkへ転送していた
既存の仕組み（Googleスプレッドシート + GAS）を、LINEへ移す。

## 実物のxlsxから読み取った事実（2026-09-05・実測）

`メッセージ管理管理v1.0 のコピー (4).xlsx` は4シート:

| シート | 中身 |
|---|---|
| 転送仕様 | **18ルール**（ランサーズ10 + ココナラ8） |
| 設定 | 受信間隔15分 / Chatwork APIトークン・アカウントID |
| ルーム一覧 | チャット名 → ルームID（959件） |
| ルーム管理 | 482件 |

**18ルールの構造**: `サイト / 送信元メール / 件名 / 送信先グループ名 / 送信内容（メールの範囲）`

送信元は2つだけ:
- `noreply@lancers.co.jp`（10件）
- `no-reply@mail.coconala.com`（8件）

**「送信内容（メールの範囲）」は7種類**:
`全文`(3) / `件名`(6) / `件名+コメント内容`(2) / `件名+メッセージ内容+URL`(2) /
`メッセージ内容+URL`(2) / `本文抜粋`(1) / `取引相手名+プロジェクト名`(1)

★件名には `<取引相手名>` `<案件名>` `(トークルームNo:XXXXXXXX)` のような
**可変部分**が含まれる。完全一致では当たらない。前方一致か正規表現が要る。

## ★最重要の発見: 既存の automations では、このままでは届かない

`POST /api/webhooks/incoming/:id/receive`（HMAC-SHA256検証つき・実装済み）は
`fireEvent(db, 'incoming_webhook.<source>', { eventData })` を呼ぶ。

しかし `event-bus.ts` の `send_message` はこうなっている:
```ts
case 'send_message': {
  if (!lineAccessToken || !friendId) break;   // ← friendId が無いと何もせず抜ける
```

**メールには friend がいない。** ランサーズから届くのであって、LINEの友だちから
届くのではない。だから既存の automations に載せても `send_message` は素通りする。

同様に `add_tag` / `start_scenario` 等も friend 前提。
**friend を持たないイベントで「管理者のLINEへ送る」経路は、現状どこにも無い**
（`notifyAdmin` 相当のものをリポジトリ全体で探したが無かった）。

→ ここが新規実装の要る唯一の箇所。**「誰のLINEへ送るか」を決める仕組みが要る。**

## 移植できるもの / 要るもの

**既にあるもの（作らない）**
- 外部からの受け口（HMAC検証つき）… `POST /api/webhooks/incoming/:id/receive`
- 受け口の管理API … `apps/worker/src/routes/webhooks.ts`
- ルールの置き場 … `automations`（conditions / actions / priority をJSONで持つ）
- ルール編集画面 … `apps/web/src/app/automations/page.tsx`
- 実行記録 … `automation_logs`

**要るもの**
1. **宛先の決め方**。案は3つ:
   - (a) 特定の friend（＝運用者自身のLINE）へ push する専用アクションを足す
   - (b) 特定アカウントの全友だちへ broadcast（★誤爆が怖い。運用者だけの窓口なら可）
   - (c) 受け口ごとに「通知先 friend_id」を持たせる
   ★どれにするかは未決。**(a) か (c) が安全**（broadcast は事故ると顧客に飛ぶ）
2. **メール本文の解析**（送信元 / 件名 / 本文の切り出し）
3. **転送範囲7種の切り出し** ← ★実物のメールが無いと決められない

## ★未確認（実物のメールが要る）

「件名+コメント内容」の**コメント内容が本文のどこか**は、xlsxには書いていない。
言葉で書いてあるだけで、区切り文字も見出しも不明。
**推測で実装しない。まず「全文」で通し、実物を見てから絞る。**

同様に「本文抜粋」「メッセージ内容+URL」「取引相手名+プロジェクト名」も未確認。

## ★セキュリティ（守ること）

- xlsxの「設定」シートに **Chatwork APIトークンが平文**で入っている。
  コードにもDBにも**書かない**。移行後は再発行を勧める。
- メール本文には取引相手の氏名・案件名が含まれる。転送先を間違えると
  第三者に個人情報が出る。**宛先の決め方(1)を安全側に倒す理由がこれ。**
