設計の中心思想（会議の収束点をそのまま採る）:
**「音声を聞かせる」ことをやめ、「声が存在すること」を静止状態で読ませる。**
そのための核となる仕掛けは一つだけ——**会話バブルを「音声のやりとりの文字起こし」としてフレーミングする**こと。バブルに「音声メッセージ・0:05」「声で返信・0:06」というチップを添え、中身のセリフを「打った文字」ではなく「喋った言葉」の字面（間・言い淀み・語尾）で書く。読者は音を出さなくても頭の中で声を再生する。動画は価値の伝達装置から降格させ、「証拠」の位置に置く。

## 先に設計判断：たぬ姉の語尾は「〜よ」を採る

**判断: knowledge-pack版「〜よ」「〜なのよ」を採用。動画版「〜のだー」は採らない。**

理由:
1. **LPが実演しているのは「顧客のLINE公式アカウントがどう喋るか」であり、Bot実応答の口調の正本は knowledge-pack の persona**（`knowledge-packs/yukkuri-exosome/persona.md` で「〜よ」「〜なのよ」の先生役として運用実績がある側）。LPのセリフは製品の出力見本なのだから、製品側の語尾に揃えるのが誠実。
2. 「〜のだー」はゆっくり動画文化の様式語尾で、応援動画（ouenmovie）の文脈でこそ生きる。LPの基調「静かで正直」の中に置くとミーム的な浮き方をし、商談検討中の訪問者に対してトーンが割れる。実際、`_docs/CHARACTER-VIDEO-DESIGN.md` L191-197 の実セリフ例でも、たぬ姉は「あらあら〜」「〜やねぇ」の柔らかい語りで「のだー」を使っていない。
3. 本セクションは3体の声の違いを語尾の対比で感じさせる設計（後述・論点E）。りんく「〜の」／こん太「〜なんだ」に対し、たぬ姉に落ち着いた「〜よ」を与えると三者の対比が最も立つ。「のだー」だとこん太の短い断定と音感が近づき、差が濁る。

用途による使い分け（動画=のだー／LP・Bot=よ）は矛盾ではなく既に確立した運用なので、LP側の正本を「〜よ」と明記して固定する。

## A. 理想の体験フロー

### 音を出さない訪問者（多数派・この設計の主役）

1. **見出し＋リード**で「声を聞き取り、声で返す」機能だと知る。リードが直後の会話例を「やりとりの文字起こし」だと宣言する。
2. **音の保証の一文**（「このページを開いただけでは音は鳴りません」）で警戒が解ける。読み進める心理コストが下がる。
3. **文字起こしカード3枚**を眺める。ユーザー側バブルに「音声メッセージ・0:05」、キャラ側バブルにアバターと「声で返信・0:06」。**声→声のやりとりだと視覚だけで分かる**。セリフは言い淀み・間・語尾が入った喋り言葉で、頭の中で音が鳴る。
4. 3枚のセリフの**リズムと語尾が全部違う**こと、注記の**VOICEVOX話者名が3人分ある**ことから、「3体それぞれに別の声がある」と理解する。役割説明は一切読まされない。
5. **動画**は「実際に動かした様子（約20秒）」という注記付きで置かれている。押さなくても、ポスター画像（LINE実画面）で「本当に動いている証拠がある」ことだけ受け取って通過できる。
6. **仕組み3行＋フォールバック宣言**で、「声が作れないときは黙らず文章で返す」という設計思想を読む。ここで「正直なサービスだ」という印象が固まる。

→ **一度も音を出さずに、価値（声で返る）・実在（3つの声）・信頼（黙らない設計）の3点が伝わる。**

### 音を出す訪問者（少数派・深く刺さる）

1〜4は同じ。5で「約20秒・こん太の声」と事前に分かった上で ▶ を押す。長さも内容も予告済みなので不意打ちがない。実際の合成音声を聞いた後にカードを見返すと、文字起こしが「さっき聞いた声の姉妹」として立体化する。

## F. 捨てた案と理由

| 捨てた案 | 理由 |
|---|---|
| ミュート自動再生＋字幕焼き込み動画 | iOS Safari（低電力モード等）でブロックされる環境があり、論点Bを満たせない。動画再編集コストも発生（ハードカット限定等の編集規約あり）。静的カードなら失敗モードが存在しない |
| LINE風の疑似再生ボタン付きバブル（▶三角を描く） | 押しても鳴らない偽アフォーダンスになり、「静かで正直」のトーンに反する。チップは「音声メッセージ・0:05」というテキスト表記に留め、操作可能に見せない |
| 波形アニメーション・イコライザ演出 | 会議発散役の指摘どおり抽象記号は「声の人格」を伝えない。CSS/JSコストの割に情報量ゼロ |
| スクロール連動のタイプライタ字幕 | JSが数十行必要になり、静的LP1セクションには過剰。動かなくても成立する設計が先 |
| キャラごとの「役割ボイスカタログ」（案内役・判定役…のラベル付き一覧） | 地雷1に正面衝突（次章） |
| 実音声ボタン3つを初手から実装 | アセット生成・実機検証（m4a再生互換）のコストが乗る。MVP案3として保留 |

## G. 地雷と回避策

1. **役割ラベルの復活（最重要）**: `KIMITOTALK-CHARACTER-USAGE-DESIGN.md` で撤回済み。本設計はキャラに**名前とアバターだけ**を添え、「対応役/判定役/安全役」等の語をLP上に一切出さない。三分類は本設計書の内部根拠（セリフの書き分け・カードの場面選定）にのみ使った。カードとシーンの組み合わせが暗黙の役割付けに読まれるリスクは「※キャラクターと場面の組み合わせも一例です」の注記で潰す。
2. **語尾の取り違え**: 正本に従い、りんく「〜の」、こん太「〜なんだ」「〜ない？」、たぬ姉「〜よ」（LPでの採用判断は冒頭に記載）。1セリフ1文・短文。実装時にセリフを改変する場合もこの語尾表から出ないこと。
3. **VOICEVOXクレジット漏れ**: 動画分（白上虎太郎）に加え、カードで3体の声に言及する以上、3話者分「VOICEVOX：冥鳴ひまり / 春日部つむぎ / 白上虎太郎」を注記に必ず入れる（D記載の文言をそのまま使う）。話者IDの正本は ouenmovie（マッピングは `_docs/demo-voice-riri/README.md` で確認済み：たぬ姉=冥鳴ひまり／りんく=春日部つむぎ／こん太=白上虎太郎）。
4. **誇張表現**: 「即座に」「完璧な声で」等を使わない。D文言は「〜することもできます」「うまく声が作れなかったときは」と、できない場合を含めて書いてある。改変時もこの水位を守る。
5. **創作イメージ注記の欠落**: 新しい会話例を載せる以上、既存の型「※会話例はサービスを説明するための創作イメージです」が必須。D文言に組み込み済み。
6. **アンチパターン（機械的自己説明・メタ漏れ・他人事描写）**: カードのセリフは接客の実演であり、キャラが自分やサービスを説明するセリフを入れない。「わたしはAIで音声合成により〜」のような台詞は書かない。
7. **自動再生依存**: いかなる形でも自動再生を前提にしない。動画は `controls playsinline preload="metadata"` の現行属性を維持し、位置と前後の文言だけ変える。

## 必答論点への回答

- **A（音を出さない訪問者に伝わるか）**: 伝わる。価値の伝達を動画から「文字起こしカード」に移した。声チップ（音声メッセージ・0:05／声で返信・0:06）が「声→声」の往復を視覚だけで示し、喋り言葉のタイポグラフィ（言い淀み・間・語尾）が頭の中で音を鳴らす。動画は証拠に降格し、押されなくても設計が完結する。
- **B（自動再生が一切効かない環境で成立するか）**: 成立する。本設計は自動再生を一箇所も使わない。動く要素は訪問者が自分で押すネイティブ動画コントロールだけで、JSも0行。iOS Safariで何がブロックされようと表示内容は1pxも変わらない。
- **C（音の警戒をどう下げるか）**: 先回りの保証で下げる。セクション冒頭に「このページを開いただけでは、音は鳴りません。音が出るのは、下の動画の ▶ を押したときだけです」を明記し、動画直前で「約20秒・こん太の声」と長さと内容を予告する。押す前に何が起きるか全部分かっている状態を作る。
- **D（フォールバックを誠実さの証明にできるか）**: できる。foundation-box 末尾の「黙り込まず、同じ内容をそのまま文章でお返しします。『返事が来ない』を作らないことを、声を出すことより優先した設計です」で、テキストフォールバックを欠陥の言い訳ではなく設計思想として宣言する。「答えられない質問は担当者へ引き継ぐ」という既存LPの正直路線と同じ文法。
- **E（役割ラベルなしで声の違いを感じさせる）**: 3つの手段の重ね掛けで解く。(1) セリフの語尾と呼吸の対比——りんくの弾む「〜の」、こん太の短い「〜なんだ／〜ない？」、たぬ姉のゆったりした「〜よ」。読めばリズムが違う。(2) VOICEVOXクレジットに**3人の別々の話者名**が並ぶこと自体が「3体それぞれに固有の声がある」ことの事実ベースの証明になる。(3) 動画で実際に聞けるのは1体（こん太）だけと明示することで、「残り2体の声もある」という余白が残る。いずれも「この子は〇〇役」という説明を一切使わない。
